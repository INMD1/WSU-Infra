## 1. VM 목록 간소화 및 상세 페이지 추가

### 📌 문제 상황

기존 대시보드에서 VM 목록이 너무 많은 정보를 한 번에 표시하고 있었습니다:
- VM 이름, 상태, IP, 포트, 비밀번호 등 모든 정보가 한 줄에 표시됨
- 각 VM 에 대해 시작/정지/삭제 버튼이 모두 표시되어 화면이 복잡함
- 사용자가 원하는 VM 의 상세 정보를 확인하려면 여러 번 클릭해야 함

### ✅ 해결 방법

**VM 목록은 핵심 정보만**, **상세 페이지에서 모든 기능**을 제공하는 2 단계 구조로 변경했습니다.

#### 변경된 화면 구조

```
대시보드 (VM 목록)
    ↓ (클릭)
VM 상세 페이지 (전체 정보 + 모든 기능)
```

## 2. SQL "Too many connections" 오류 방지

### 📌 문제 상황

여러 사용자가 동시에 접속하거나 많은 요청이 들어오면 MySQL 이 다음과 같은 오류를 발생시킵니다:

```
Error: Too many connections
```

**원인:** MySQL 이 동시에 허용하는 연결 수 (기본값 151) 를 초과했을 때 발생

---

### ✅ 해결 방법

데이터베이스 연결을 효율적으로 관리하는 **연결 풀 (Connection Pool)** 설정을 추가했습니다.

---

### 📝 코드 변경 사항

#### 2.1 데이터베이스 연결 설정 (`src/db/index.ts`)

**변경 전:**
```typescript
export const connection = mysql.createPool(process.env.DATABASE_URL);
```

**변경 후:**
```typescript
export const connection = mysql.createPool({
  uri: process.env.DATABASE_URL,
  waitForConnections: true,
  connectionLimit: parseInt(process.env.DB_POOL_SIZE || '10'),
  minConnections: parseInt(process.env.DB_POOL_MIN || '2'),
  acquireTimeout: parseInt(process.env.DB_POOL_ACQUIRE_TIMEOUT || '60000'),
  queueLimit: parseInt(process.env.DB_POOL_QUEUE_LIMIT || '0'),
  connectTimeout: parseInt(process.env.DB_CONNECT_TIMEOUT || '10000'),
  maxIdle: parseInt(process.env.DB_POOL_MAX_IDLE || '10'),
  idleTimeout: parseInt(process.env.DB_POOL_IDLE_TIMEOUT || '60000'),
  enableKeepAlive: true,
  keepAliveInitialDelay: 0,
});
```

---

### 🔧 설정 옵션 설명

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `connectionLimit` | 10 | 동시에 유지할 최대 연결 수 |
| `minConnections` | 2 | 항상 유지할 최소 연결 수 (빠른 응답) |
| `acquireTimeout` | 60000 | 연결 대기 최대 시간 (ms) |
| `queueLimit` | 0 | 대기열 제한 (0=무한) |
| `connectTimeout` | 10000 | 연결 시도 제한 시간 (ms) |
| `maxIdle` | 10 | 유휴 연결 최대 수 |
| `idleTimeout` | 60000 | 유휴 연결 유지 시간 (ms) |

---

### 🔑 주요 옵션 자세히 설명

#### 1. `connectionLimit` (최대 연결 수)

**의미:** 데이터베이스와 동시에 유지할 수 있는 최대 연결 수

**설정 가이드:**
```
작은 서버:  5-10
중형 서버:  10-20  
큰 서버:    20-50
```

#### 2. `minConnections` (최소 연결 수)

**의미:** 항상 유지할 연결 수 (미리 만들어 두는 연결)

**왜 필요한가?**
- 요청이 들어오면 매번 새 연결을 만들면 느림
- 미리 2 개 정도 만들어 두면 빠른 응답 가능

#### 3. `waitForConnections: true`

**의미:** 연결이 모두 사용 중일 때 바로 에러를 내지 않고 대기

**동작:**
```
연결 10 개 모두 사용 중
     ↓
새로운 요청 들어옴
     ↓
waitForConnections=true → 대기열에排隊
waitForConnections=false → 바로 에러 ("Too many connections")
```

#### 4. `queueLimit` (대기열 제한)

**의미:** 대기할 수 있는 최대 요청 수

- `0` = 무한히 대기 (기본)
- `100` = 100 개 이상 대기하면 에러

---

### 📋 환경 변수 추가 (`.env`)

```env
# 연결 풀 설정 (Too many connections 방지)
DB_POOL_SIZE=10           # 최대 연결 수
DB_POOL_MIN=2            # 최소 연결 수
DB_POOL_ACQUIRE_TIMEOUT=60000  # 연결 획득 제한 시간 (ms)
DB_POOL_QUEUE_LIMIT=0    # 대기열 제한 (0=무한)
DB_CONNECT_TIMEOUT=10000 # 연결 시도 제한 시간 (ms)
DB_POOL_MAX_IDLE=10      # 유휴 연결 최대 수
DB_POOL_IDLE_TIMEOUT=60000   # 유휴 연결 유지 시간 (ms)
```

---

### 🎯 결과

**이전:** 많은 요청 → 연결 초과 → "Too many connections" 오류
**이후:** 많은 요청 → 연결 풀에서 효율적 관리 → 안정적 응답

## 3. 포트포워딩 API 수정

### 📌 문제 상황

VM 상세 페이지에서 포트포워딩을 추가할 때 다음 오류가 발생했습니다:

```json
{
  "success": false,
  "message": "internal_ip and internal_port are required"
}
```

**원인:** 프론트엔드는 `vm_id`만 보내지만, API 는 `internal_ip`를 요구함

---

### ✅ 해결 방법

API 가 `vm_id`만 받아도 자동으로 해당 VM 의 `internal_ip`를 조회하도록 수정했습니다.

---

### 📝 코드 변경 사항 (`src/app/api/port-forwards/route.ts`)

**변경 전:**
```typescript
export async function POST(request: Request) {
  const body = await request.json();
  const { internal_ip, internal_port, ... } = body;
  
  // internal_ip 필수 체크
  if (!internal_ip || internal_port === undefined) {
    return NextResponse.json(
      { success: false, message: 'internal_ip and internal_port are required' },
      { status: 400 }
    );
  }
  
  // ... 포트포워딩 생성
}
```

**변경 후:**
```typescript
export async function POST(request: Request) {
  const body = await request.json();
  const { vm_id, internal_port, ... } = body;
  
  // vm_id 필수 체크
  if (!vm_id || internal_port === undefined) {
    return NextResponse.json(
      { success: false, message: 'vm_id and internal_port are required' },
      { status: 400 }
    );
  }
  
  // VM 의 internal_ip 자동 조회
  const vm = await db.select({ internal_ip: vms.internal_ip })
    .from(vms)
    .where(eq(vms.vm_id, vm_id))
    .get();
    
  if (!vm?.internal_ip) {
    return NextResponse.json(
      { success: false, message: 'VM not found' },
      { status: 404 }
    );
  }
  
  // internal_ip 를 자동으로 사용하여 포트포워딩 생성
  const rule = await portForwardService.create({
    vmId: vm_id,
    internalIp: vm.internal_ip,  // 자동으로 조회된 IP 사용
    internalPort: Number(internal_port),
    // ...
  });
}
```

---

### 🔄 API 요청 비교

**변경 전 (오류 발생):**
```json
POST /api/port-forwards
{
  "vm_id": "abc-123-def",
  "internal_port": 8080
}
```
→ ❌ `{ success: false, message: "internal_ip and internal_port are required" }`

**변경 후 (성공):**
```json

{
  "vm_id": "abc-123-def",
  "internal_port": 8080
}
```
→ ✅ API 가 자동으로 `vm_id`로 VM 조회 → `internal_ip` 추출 → 포트포워딩 생성
